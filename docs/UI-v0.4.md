# v0.4：透明桌面窗口与全框字幕

## 路线变化

用户要求桌面置顶必须透出其他应用。Chromium Document PiP 无桌面透明 API，因此新版「桌面置顶」改为 Windows WPF 原生窗口。新增 nativeMessaging 权限，沿用原字幕域名权限，不增加 cookies 或本地网络域名权限。

扩展 → 隔离世界 → 后台白名单桥 → 浏览器标准输入/输出 → WPF 窗口。窗口只收到字幕与播放/外观状态，命令只允许播放控制及外观调整。没有网络监听端口，也没有文件访问或执行命令的消息接口。

安装需要将 native/Install.ps1 注册到当前用户 Chrome/Edge 的 NativeMessagingHosts，并提供用户自己的扩展 ID；本轮没有替用户修改注册表、接受扩展权限或读取浏览器资料。

## 已实测：独立离线浏览器

- 默认192px窗口中，空闲字幕区域180px，上下只留6px边距。
- 移入显示控制时区域117px；离开恢复180px，不保留隐藏工具栏空位。
- 拖动、八方向缩放、几何持久化、连续排版、长句完整显示、手动滚动暂停跟随均通过。
- 同一短句样本下18px可见16句，14px可见28句，包含边缘部分可见句；具体取决于文本长度。
- 证据：evidence/ui-v4-checks.json、ui-v4-idle.png、ui-v4-hover.png。

## 自动化验证

36项 JavaScript 测试通过，覆盖原字幕与播放模块，以及新增双向消息白名单、长度边界、来源限制、单活动连接、握手超时、断开恢复、原生开启后页内隐藏和返回恢复。安装器在 PowerShell 5 中通过模拟注册表测试，确认生成的宿主清单和 HKCU 路径正确；该测试没有修改注册表。

原生程序实际运行的离屏验证也已通过（native/Test.cjs）：

- HWND 同时具有 WS_EX_LAYERED 与 WS_EX_TOPMOST，AllowsTransparency=true。
- 192px高的窗口，字幕区域184px；鼠标移出没有工具栏占位。
- 100%设置的渲染背景alpha=1/255，文字alpha=255，透明度互相独立。
- 1600字字幕完整换行，高1440px，定位从句首开始；手动阅读不会被强制拉回。
- 原生控件播放、倍速、外观命令测试通过。
- 实际exe标准输入/输出协议通过 ready、分片数据、状态消息、关闭和正常退出测试。

详见 evidence/native-checks.json 与 evidence/native-protocol-checks.json。原生截图只渲染工具自己的离屏窗口，不包含其他应用或桌面内容。

## 需要安装后的手动验收

1. 重新加载扩展，按需确认新增 nativeMessaging 权限。运行一次 native/Install.cmd，填入本扩展ID。
2. 刷新有字幕的 B 站视频页，点击「桌面置顶」；出现无浏览器标题栏的透明窗口，原页内框隐藏。
3. 外观设置将背景透明度调到95%与100%，确认文字保持清晰、能透出后方窗口。100%保留1/255极淡背景用于鼠标命中。
4. 鼠标移入显示控制，移出后整个字幕框用于字幕；拖顶部移动、拖边框缩放。
5. 播放/暂停、快进退、倍速、点击字幕跳转，与原视频核对；手动滚动长句后不自动抢回，点「跟随播放」恢复。
6. 点「回到页内」，确认原框位置尺寸恢复；再次置顶应能重开。
7. 由用户自行将其他应用切到前台，确认透明且置顶，观察后台播放60秒是否持续同步。本轮未执行该跨应用验收。
8. 刷新或整页切集会关闭透明窗口，需再次打开；这是已知限制。同页切视频应更新字幕。

## 假设与限制

- 在用户当前 Windows 环境实现；macOS没有原生助手。
- 桌面使用连续排版，页内可选逐句换行。
- 当前仅一个B站页面可以占用助手；避免多视频争用播放控制。
- 不承诺鼠标穿透。100%透明仍保留极淡命中层，使拖动和唤出控制可用。
- 安装/浏览器端 nativeMessaging 连通与登录态 B 站播放，本轮尚未真机复验；离线和原生自测不能冒充完整实机验收。
